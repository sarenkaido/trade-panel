# پنل آلارم قیمت

یک سایت شخصی برای آلارم قیمت ارز و سهام. آلارم‌هایت را در سایت می‌سازی و وقتی قیمت به هدف رسید، **پیامش در تلگرام** (و اختیاری ایمیل) می‌آید. روی Cloudflare Worker اجرا می‌شود و **رایگان است**.

## امکانات
- ثبت‌نام و ورود با ایمیل و رمز
- آلارم‌های Long / Short (یا بدون جهت) با چند هدف
- قیمت زنده، فیلتر و دسته‌بندی
- تب‌های سناریو، پوزیشن‌ها، استراتژی، ترید تسک و واچ‌لیست (متن + دسته‌بندی)
- **ماشین‌حساب پوزیشن (ساده):** فقط شش عدد وارد می‌کنی: سرمایه، درصد ریسک، لوریج، قیمت ورود، حد ضرر و (اختیاری) حد سود. جهت لانگ/شورت خودکار از روی حد ضرر تشخیص داده می‌شود و دکمه‌های 1R و 2R و 3R حد سود را خودشان پر می‌کنند. نتیجه یک نمودار سود/ضرر مثل TradingView و مارجین لازم، حجم پوزیشن و تعداد است. کارمزد و نحوه‌ی محاسبه در بخش‌های جمع‌شده هستند و مقادیر حساب در مرورگر یادت می‌ماند.
- **تب دلخواه:** با دکمه‌ی «＋ تب جدید» تب خودتان را با نام و آیکون بسازید و هر چه خواستید داخلش بنویسید (ذخیره‌ی خودکار؛ تا ۱۰ تب؛ با ✎ ویرایش یا حذف می‌شود). تب‌های دلخواه جدا از تب‌های اصلی نشان داده می‌شوند و داخل هر کدام نوت‌ها مثل تب «سناریو» به شکل کارت هستند (عنوان اختیاری، جستجو، ✎ ویرایش، 🗑 حذف، دکمه‌ی «＋ نوت جدید»؛ تا ۳۰ نوت)
- طراحی «کاغذ نمودار»: پس‌زمینه‌ی شطرنجی، خط‌کش قیمت روی هر آلارم، تم تیره و روشن
- فارسی و انگلیسی
- با پنل باز، تیک آلارم در چند ثانیه نشان داده می‌شود؛ بدون پنل، چک خودکار هر دقیقه (با کندل‌های ۱ دقیقه‌ای؛ اگر قیمت فقط با یک سایه به هدف بخورد هم آلارم می‌آید)

ساز و کار داخلی: [ARCHITECTURE.md](ARCHITECTURE.md)

## راه‌اندازی

برای نصب پروژه، ابتدا یک کپی از مخزن در حساب GitHub خودت بساز و سپس یکی از دو روش زیر را انتخاب کن. انتشار برنامه از طریق GitHub Actions انجام می‌شود؛ هر بار خودت مقصد انتشار را انتخاب می‌کنی.

### ۱. آماده‌سازی مخزن شخصی

1. وارد حساب GitHub خودت شو و در همین صفحه روی **Fork** بزن: [ساخت Fork از پروژه](https://github.com/sarenkaido/trade-panel/fork).
2. مخزن Forkشده را باز کن و از تب **Actions**، در صورت نمایش پیام غیرفعال بودن گردش‌کارها، گزینه‌ی **I understand my workflows, go ahead and enable them** را بزن.
3. وارد **Settings → Secrets and variables → Actions** شو. در مراحل بعد، مقادیر لازم را در همین قسمت و فقط در مخزن خودت اضافه می‌کنی.
4. هیچ توکن، رمز یا شناسه‌ی حساب خودت را در مخزن عمومی اصلی یا در فایل‌های کد قرار نده.

### ۲. نصب نسخه وب روی Cloudflare

این روش پنل را به شکل یک سایت مستقل در مرورگر در دسترس قرار می‌دهد.

**الف) ساخت فضای ذخیره‌سازی**
1. در [Cloudflare](https://dash.cloudflare.com/) یک حساب بساز یا وارد حساب خودت شو.
2. از بخش **Storage & Databases → KV** یک Namespace بساز؛ مثلاً نام آن را `trade-panel` بگذار.
3. شناسه‌ی Namespace (Namespace ID) را کپی کن.

**ب) ساخت API Token**
1. در Cloudflare به **My Profile → API Tokens** برو و یک Token بساز.
2. دسترسی لازم برای انتشار و مدیریت Worker را به آن بده و آن را به حساب خودت محدود کن.
3. مقدار Token و **Account ID** حساب Cloudflare را بردار.

**ج) افزودن مقادیر به GitHub**
در مخزن Forkشده به **Settings → Secrets and variables → Actions → New repository secret** برو و این سه Secret را بساز:

| نام Secret | مقداری که باید وارد کنی |
|---|---|
| `CLOUDFLARE_API_TOKEN` | API Token ساخته‌شده در Cloudflare |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID حساب Cloudflare |
| `KV_NAMESPACE_ID` | شناسه‌ی KV Namespace مرحله‌ی قبل |

اتصال D1 اختیاری است؛ اگر از D1 استفاده می‌کنی، شناسه‌ی دیتابیس را با نام `D1_DATABASE_ID` به‌عنوان Secret اضافه کن. در غیر این صورت نیازی به آن نیست.

**د) انتشار**
1. در مخزن خودت به **Actions → Deploy Trade Panel** برو.
2. روی **Run workflow** کلیک کن.
3. مقصد **فقط نسخه وب — Cloudflare Worker** را انتخاب کن و اجرای workflow را تأیید کن.
4. پس از سبز شدن مراحل انتشار، در Cloudflare وارد **Workers & Pages** شو و آدرس Worker ساخته‌شده را باز کن.

**هـ) راه‌اندازی اولیه سایت**
1. آدرس Worker را در مرورگر باز کن و ثبت‌نام را شروع کن.
2. برای ارسال کد تأیید ایمیل، یک حساب در [Resend](https://resend.com/) بساز و API Key آن را طبق راهنمایی که پنل هنگام ثبت‌نام نشان می‌دهد وارد کن. در حساب رایگان Resend، ارسال بدون دامنه‌ی تأییدشده محدود است؛ دستورالعمل و محدودیت فعلی Resend را بررسی کن.
3. پس از تأیید ایمیل وارد پنل شو. اتصال ربات تلگرام از تنظیمات پنل اختیاری است و فقط برای دریافت اعلان‌ها استفاده می‌شود.

### ۳. نصب Telegram Mini App

این روش پنل را داخل تلگرام باز می‌کند. برای آن به ربات تلگرام، پروژه‌ی Telegram Mini App در TGCLOUD و Cloudflare برای اجرای بررسی دوره‌ای آلارم‌ها نیاز داری.

**الف) ساخت ربات تلگرام**
1. در تلگرام [@BotFather](https://t.me/BotFather) را باز کن و دستور `/newbot` را بفرست.
2. نام و شناسه‌ی ربات را انتخاب کن و Bot Token را در جای امن نگه دار.

**ب) ساخت برنامه در TGCLOUD**
1. در سرویس [TGCLOUD](https://tgcloud.ai/) حساب بساز و یک پروژه‌ی Telegram Serverless / Mini App ایجاد کن.
2. توکن دسترسی همان پروژه را از پنل TGCLOUD بردار. این توکن باید مربوط به همین برنامه باشد، نه Bot Token تلگرام.

**ج) آماده‌سازی Cloudflare**
1. یک حساب Cloudflare داشته باش.
2. یک API Token با دسترسی انتشار Worker بساز و Account ID حساب را بردار.

**د) افزودن مقادیر به GitHub**
در مخزن Forkشده به **Settings → Secrets and variables → Actions** برو و این مقادیر را اضافه کن:

| نام | نوع | مقدار |
|---|---|---|
| `TGCLOUD_TOKEN` | Secret | توکن پروژه‌ی TGCLOUD |
| `CLOUDFLARE_API_TOKEN` | Secret | API Token کلادفلر |
| `TELEGRAM_BOT_TOKEN` | Secret | توکن ربات ساخته‌شده با BotFather |
| `CLOUDFLARE_ACCOUNT_ID` | Secret یا Variable | Account ID کلادفلر |

**هـ) انتشار Mini App**
1. به **Actions → Deploy Trade Panel → Run workflow** برو.
2. مقصد **نسخه تلگرام — Telegram Mini App** را انتخاب کن و workflow را اجرا کن.
3. صبر کن تمام مراحل مربوط به انتشار Mini App و Worker زمان‌بندی آلارم‌ها با موفقیت تمام شوند.
4. ربات خودت را در تلگرام باز کن و **Start** را بزن؛ سپس دکمه‌ی Mini App را برای باز کردن پنل انتخاب کن.

در این روش ورود با حساب تلگرام انجام می‌شود و ثبت‌نام ایمیلی نسخه وب لازم نیست.

### نصب دستی بدون GitHub Actions

اگر نمی‌خواهی مخزن را به GitHub Actions وصل کنی، می‌توانی نسخه وب را کاملاً از داشبورد Cloudflare منتشر کنی. برای Telegram Mini App هم می‌توانی از رابط گرافیکی BotFather استفاده کنی: این بخش امکان ویرایش ماژول‌های سرور، دیتابیس و بارگذاری فایل‌های Mini App را دارد. برای این پروژه، مراحل دقیق کپی فایل‌ها و ساخت Worker زمان‌بندی‌شده در ادامه آمده است.

#### روش دستی A — انتشار نسخه وب فقط با داشبورد Cloudflare

**۱) ساخت KV**
1. وارد [داشبورد Cloudflare](https://dash.cloudflare.com/) شو.
2. از **Storage & Databases → KV** یک Namespace جدید بساز.
3. نامی مثل `trade-panel` انتخاب کن و صفحه را باز نگه دار.

**۲) ساخت Worker و وارد کردن کد**
1. از **Workers & Pages** گزینه‌ی ساخت برنامه / Worker را انتخاب کن.
2. یک Worker جدید بساز و وارد **Edit code** شو.
3. در مخزن پروژه، فایل [worker.js](https://github.com/sarenkaido/trade-panel/blob/Main/worker.js) را باز کن؛ محتوای کامل فایل را کپی کن و جای کد نمونه در ویرایشگر Cloudflare قرار بده.
4. نام Worker را ذخیره کن و در تنظیمات آن، Compatibility date را روی `2026-01-01` یا تاریخ جدیدتر قرار بده.

**۳) اتصال KV**
1. در صفحه Worker به **Settings → Bindings** برو و **Add → KV Namespace** را انتخاب کن.
2. نام متغیر (Variable name) را دقیقاً `ALERTS_KV` بگذار.
3. Namespace ساخته‌شده در مرحله‌ی اول را انتخاب و ذخیره کن.

**۴) فعال‌کردن بررسی خودکار آلارم‌ها**
1. به **Settings → Triggers** یا بخش **Cron Triggers** برو.
2. یک Cron Trigger با عبارت `* * * * *` اضافه کن تا بررسی آلارم‌ها هر دقیقه اجرا شود.
3. تغییرات را ذخیره و Worker را Deploy کن.

**۵) بررسی**
- آدرس `workers.dev` نمایش‌داده‌شده در صفحه Worker را باز کن.
- یک حساب بساز و وارد پنل شو.
- برای اطمینان از اجرای بررسی خودکار، در پنل به **تنظیمات → لاگ** برو و وضعیت آخرین بررسی را ببین.

**اتصال اختیاری D1:** اگر می‌خواهی به‌جای KV از D1 هم استفاده کنی، دیتابیس را در Cloudflare بساز و از **Settings → Bindings → Add → D1 database** آن را با نام متغیر دقیقاً `DB` به Worker وصل کن. برای مهاجرت خودکار داده‌های قدیمی، KV را حذف نکن.

> این روش فقط برای نسخه وب است. فایل `worker.js` به‌تنهایی Telegram Mini App را نصب نمی‌کند.

#### روش دستی B — Telegram Mini App با رابط گرافیکی BotFather

برای این مسیر لازم نیست GitHub Actions یا CLI انتشار TGCLOUD را اجرا کنی. خود BotFather بخش Serverless دارد که از طریق آن می‌توانی کدهای سمت سرور، دیتابیس و فایل‌های Mini App را با رابط گرافیکی مدیریت کنی. برای این پروژه فقط یک Worker زمان‌بندی‌شده در Cloudflare هم لازم است.

**۱) ساخت ربات و فعال‌سازی Serverless**
1. در تلگرام [@BotFather](https://t.me/BotFather) را باز کن و با دستور `/newbot` یک ربات بساز.
2. ربات را از فهرست **My Bots** انتخاب کن.
3. وارد بخش **Serverless** شو و آن را فعال کن.

**۲) آماده‌کردن فایل‌های پروژه**
1. از [مخزن پروژه](https://github.com/sarenkaido/trade-panel) گزینه‌ی **Code → Download ZIP** را بزن و فایل را استخراج کن.
2. برای رابط Mini App، فایل `index.html` در ریشه‌ی پروژه همان فایل نهایی قابل میزبانی است؛ لازم نیست آن را کامپایل کنی. آن را برای بارگذاری در بخش Mini App Files آماده نگه دار.
3. فایل‌های زیر را از پوشه‌ی `tgcloud` پروژه باز کن. در مراحل بعد محتوای هر فایل را در ماژول هم‌نام داخل BotFather قرار می‌دهی:
   - `tgcloud/schema.js`
   - `tgcloud/handlers/message.js`
   - `tgcloud/endpoints/api.js`
   - `tgcloud/endpoints/cron.js`
   - `tgcloud/endpoints/profile.js`
   - `tgcloud/lib/config.js`

**۳) ثبت ماژول‌ها در BotFather**
در صفحه‌ی ربات به **Serverless** برگرد و فایل‌ها را در بخش‌های مربوط قرار بده:

| بخش در BotFather | نام ماژول | فایل پروژه |
|---|---|---|
| Database / Schema | `schema.js` | `tgcloud/schema.js` |
| Handlers | `message` | `tgcloud/handlers/message.js` |
| Endpoints | `api` | `tgcloud/endpoints/api.js` |
| Endpoints | `cron` | `tgcloud/endpoints/cron.js` |
| Endpoints | `profile` | `tgcloud/endpoints/profile.js` |
| Library | `config` | `tgcloud/lib/config.js` |

برای هر ماژول، محتوای فایل متناظر را کامل جایگزین کن و Save بزن. نام ماژول‌ها و مسیرها را دقیقاً مطابق جدول نگه دار؛ فایل‌ها یکدیگر را با همین نام‌ها وارد می‌کنند.

**۴) تنظیم آدرس Mini App**
1. شناسه‌ی برنامه را از بخش Serverless / CLI Access توکن دسترسی برنامه بردار؛ توکن را لازم نیست جایی منتشر کنی. App ID بخش عددی بعد از `app` و قبل از `:` است.
2. در ماژول Library با نام `config`، مقدار `APP_ID` در آدرس `https://appAPP_ID.tgcloud.ai/` را با شناسه‌ی خودت جایگزین کن.
3. تغییر را Save کن.

**۵) بارگذاری رابط کاربری**
1. در بخش **Serverless → Mini App Files** فایل `index.html` ریشه‌ی پروژه را بارگذاری کن.
2. مطمئن شو فایل به‌عنوان صفحه‌ی اصلی Mini App یعنی `index.html` قرار گرفته است.
3. آدرس برنامه از قالب `https://app<APP_ID>.tgcloud.ai/` ساخته می‌شود.

**۶) اعمال ساختار دیتابیس**
به بخش **Serverless → Database** برو. تعریف جدول‌ها باید از `schema.js` ثبت شده باشد؛ تغییرات Schema را بررسی و گزینه‌ی Apply / Save یا اجرای Migration را بزن تا جدول‌ها ساخته شوند. تا قبل از اعمال Schema، endpointها نمی‌توانند داده‌ها را ذخیره کنند.

**۷) ساخت Worker زمان‌بندی‌شده در Cloudflare**
این Worker هر دقیقه endpoint داخلی تلگرام را صدا می‌زند تا آلارم‌ها بررسی شوند.

1. وارد [داشبورد Cloudflare](https://dash.cloudflare.com/) شو و از **Workers & Pages** یک Worker جدید بساز.
2. فایل [worker/src/index.js](https://github.com/sarenkaido/trade-panel/blob/Main/worker/src/index.js) را باز کن، کل محتوایش را در **Edit code** جایگزین کد نمونه کن.
3. Compatibility date را روی `2026-11-01` یا جدیدتر قرار بده.
4. در **Settings → Variables and Secrets** یک متغیر متنی به نام `TGCLOUD_APP_URL` بساز و آدرس واقعی برنامه، مثل `https://app123456.tgcloud.ai`، را در آن قرار بده.
5. یک Secret به نام `TELEGRAM_BOT_TOKEN` بساز و Bot Token معمولی BotFather را در آن وارد کن.
6. در **Settings → Triggers → Cron Triggers** عبارت `* * * * *` را اضافه کن.
7. Worker را Deploy کن.

**۸) تنظیم دکمه‌ی ورود و آزمایش**
1. در تنظیمات BotFather، آدرس Mini App خودت را به‌عنوان Main Mini App یا Menu Button ثبت کن.
2. ربات را باز کن و Start بزن؛ پیام ربات باید دکمه‌ی «باز کردن پنل هشدار قیمت» را نمایش بدهد.
3. دکمه را بزن و بررسی کن پنل داخل تلگرام باز شود.
4. یک آلارم آزمایشی بساز و پس از یک دقیقه وضعیت آن را بررسی کن.

> **نکته:** رابط گرافیکی BotFather برای ویرایش ماژول‌ها، دیتابیس و Mini App Files در مستندات رسمی Telegram Serverless معرفی شده است. این مسیر دستی است و باید فایل‌ها را خودت در ماژول‌های هم‌نام کپی کنی؛ اگر می‌خواهی فایل‌ها خودکار همگام و منتشر شوند، روش CLI یا GitHub Actions ساده‌تر است.

**منابع رسمی:** [Telegram Serverless — مدیریت پروژه از BotFather و CLI](https://core.telegram.org/bots/serverless)، [Cloudflare — ویرایش و انتشار Worker از داشبورد](https://developers.cloudflare.com/workers/).

### انتشار نسخه‌های بعدی

برای انتشار به‌روزرسانی‌ها، تغییرات را به مخزن Forkشده‌ی خودت بفرست؛ سپس از **Actions → Deploy Trade Panel → Run workflow** مقصد موردنظر را انتخاب و اجرا کن. انتشار خودکار با هر Push انجام نمی‌شود.

### نکات مهم
- این دو روش مستقل‌اند. اگر فقط نسخه وب را می‌خواهی، مراحل Telegram Mini App را انجام نده؛ و برعکس.
- مقادیر جدول‌ها نام تنظیمات موردنیاز برنامه‌اند، نه اطلاعات حساب سازنده‌ی پروژه. هر کاربر باید مقادیر متعلق به حساب خودش را در مخزن Forkشده‌ی خودش وارد کند.
- Secretها در مخزن عمومی نمایش داده نمی‌شوند. آن‌ها را در کد، Issue، پیام عمومی یا فایل README قرار نده.
- اگر اجرای workflow ناموفق شد، در تب Actions همان اجرا را باز کن و اولین مرحله‌ی قرمز را بررسی کن.
- برای جزئیات معماری و ساختار فنی پروژه، [ARCHITECTURE.md](ARCHITECTURE.md) را ببین.

## اولین استفاده

**نسخه وب:** آدرس Worker را باز کن، ثبت‌نام ایمیلی را انجام بده و پس از تأیید وارد شو. برای دریافت اعلان تلگرام، از تنظیمات پنل ربات خودت را متصل کن.

**Telegram Mini App:** ربات خودت را باز کن، Start را بزن و دکمه‌ی Mini App را انتخاب کن.

### ساخت اولین آلارم

در پنل، دکمه‌ی **＋ آلارم جدید** را بزن، نماد دارایی (مثل BTC) و قیمت هدف را وارد کن و ذخیره کن.

## ذخیره‌سازی و دیتابیس

نسخه وب به‌صورت پیش‌فرض از Cloudflare KV استفاده می‌کند. در صورت نیاز می‌توانی D1 را نیز با افزودن Secret اختیاری `D1_DATABASE_ID` به مخزن خودت فعال کنی. شناسه‌ی دیتابیس باید متعلق به حساب Cloudflare خودت باشد.

## سهام و کوین‌ها

- **کوین:** فقط نامش را بنویس (`BTC`، `ETH`، ...).
- **سهام:** فقط نماد را بنویس (`AMZN`، `TSLA`، `NVDA`، ...)؛ سایت خودش `USDT.P` را ته آن می‌گذارد (مثلاً `AMZNUSDT.P`) و قیمت را از بازار فیوچرز صرافی‌ها می‌گیرد. هر نمادی را هم که خودت با `.P` تمام کنی همین‌طور حساب می‌شود.
- در ⚙️ تنظیمات ← «لاگ»، اگر همه‌چیز درست باشد پیام سبز «✅ همه چیز سالم است» را می‌بینی؛ در غیر این صورت دلیل مشکل (مثلاً کوینی که قیمتش گرفته نمی‌شود) همان‌جا نوشته می‌شود.

## نصب روی گوشی یا کامپیوتر (مثل یک اپ)

سایت یک وب‌اپ است و می‌شود آن را نصب کرد:
- **اندروید (Chrome):** منوی ⋮ ← «Install app» یا «Add to Home screen».
- **آیفون (Safari):** دکمه‌ی Share ← «Add to Home Screen».
- **کامپیوتر (Chrome/Edge):** آیکون نصب در نوار آدرس.

بعد از نصب، بدون نوار مرورگر و تمام‌صفحه باز می‌شود؛ تب‌ها روی موبایل پایین صفحه‌اند و دکمه‌ی «برگشت» بین تب‌ها کار می‌کند. آخرین تبی که باز بود یادش می‌ماند.

## اگر مشکلی پیش آمد
| مشکل | راه حل |
|---|---|
| سایت ارور ۵۰۰ می‌دهد | داشبورد ← ورکر ← **Logs** را نگاه کن. اگر نوشته «limit exceeded»، سهمیه‌ی رایگان KV پر شده و ساعت ۰۰:۰۰ UTC ریست می‌شود |
| می‌گوید KV وصل نیست | مرحله‌ی «وصل کردن KV» را چک کن؛ اسم متغیر باید دقیقاً `ALERTS_KV` باشد |
| آلارم نمی‌آید | ⚙️ تنظیمات ← «لاگ» را باز کن: آنجا قیمت الان و فاصله‌ی هر آلارم تا هدفش و نتیجه‌ی آخرین پیام تلگرام (ارسال شد / چرا نشد) نوشته شده. اگر پیام ارسال نشود، آلارم از دست نمی‌رود و دوباره تلاش می‌شود. همچنین Cron باید `* * * * *` باشد |
| پیام تلگرام نمی‌آید | تنظیمات ← «تست تلگرام»؛ مطمئن شو در ربات **Start** زده‌ای |
| هر پیام دو بار می‌آید | یک ورکر قدیمی هنوز Cron دارد؛ آن را غیرفعال کن |
| دیپلوی ناموفق شد | گزارش اجرای استقرار و تنظیمات سرویس میزبانی را بررسی کن؛ معمولاً یکی از اتصال‌ها یا مقادیر محیطی درست پیکربندی نشده است |

## نکات
- **رمز عوض کردن:** تنظیمات ← «حساب». با تغییر رمز، نشست‌های دیگر بسته می‌شوند.
- **امنیت:** توکن ربات و کلید Resend در KV ذخیره می‌شوند و به مرورگر برنمی‌گردند.
- **پاک کردن KV** یعنی پاک شدن حساب و آلارم‌ها.
- **سقف رایگان:** ۱۰۰۰ نوشتن KV در روز؛ کد فقط وقتی چیزی تغییر کند می‌نویسد.
- ۵ ورود ناموفق، IP را ۱۰ دقیقه قفل می‌کند.
